# Module 2: Document Ingestion + Custom RAG

⚠️ **Medium-Complex** — Multi-phase plan. The provider abstraction and tool-calling flow are the most novel pieces; ingestion and frontend are mechanical but large.

## Context

Module 1 used OpenAI's Responses API (Threads/Runs/Assistants), which is an OpenAI-proprietary managed RAG system — a black box. Module 2 replaces it entirely (Option A: clean removal) with the standard **Chat Completions API**, which is OpenAI-compatible and works with OpenRouter, Ollama, LM Studio, or any provider that exposes `/v1/chat/completions`. This unlocks provider choice and forces us to manage things OpenAI previously handled: chat history, memory, and retrieval.

This plan also adds the full document ingestion pipeline: upload → chunk → embed → pgvector, and a retrieval function the LLM can call as a tool.

---

## Architectural Decisions

### 1. LLM Provider Abstraction

**Decision**: Config-driven single client, no factory or class hierarchy.

The OpenAI Python SDK handles provider abstraction natively via `base_url` and `api_key` constructor params. We initialize one `openai.OpenAI` client at module import time in `services/llm_service.py`:

```python
client = OpenAI(
    base_url=settings.llm_base_url,   # e.g. "https://openrouter.ai/api/v1"
    api_key=settings.llm_api_key,     # OpenRouter key
)
```

Config additions (flat fields in `Settings`):
- `llm_base_url` — e.g. `https://openrouter.ai/api/v1` (OpenRouter), `http://localhost:11434/v1` (Ollama)
- `llm_api_key` — provider API key (`"ollama"` for Ollama, any string for LM Studio)
- `llm_model` — e.g. `openai/gpt-4o-mini` (OpenRouter format), `llama3.2` (Ollama)
- `llm_system_prompt` — configurable without code changes

**Embeddings**: OpenRouter does not expose an embeddings endpoint. We keep `openai_api_key` in config and use a **separate `OpenAI` client** pointed at `https://api.openai.com/v1` for `text-embedding-3-small`. This is a deliberate architectural split: chat completions via any compatible provider, embeddings via OpenAI directly (or any embedding endpoint via `embedding_base_url`/`embedding_api_key` if needed later).

### 2. Chat History Management

Since the Chat Completions API is stateless, we own history. For every request:
1. Load all prior messages for the thread from Supabase (`created_at ASC`)
2. Build messages array: `[system, ...history, {role: "user", content: current_msg}]`
3. Send to `client.chat.completions.create(messages=..., model=..., stream=True)`

No truncation strategy for Module 2 — send full history. Context limits become a Module 3+ concern.

### 3. Tool Calling Flow (Retrieval)

The retrieval tool is a standard OpenAI function tool. The streaming flow has two passes:

```
Pass 1: Stream with tools=[retrieve_chunks] + stream=True
  → If stream emits tool_call delta chunks: accumulate tool call args
  → Stop streaming, execute vector search in Python
  → Append tool result message to history

Pass 2: Stream again without tools, with tool result in history
  → Yield text delta chunks to client as SSE
```

This is the standard "tool-use interrupt" pattern for streaming + function calling. No changes to the SSE format the frontend consumes.

### 4. Ingestion Pipeline

- **Upload**: `POST /ingest/upload` (multipart) → stores file in Supabase Storage → inserts `documents` row + `ingestion_jobs` row (status: `pending`) → triggers `BackgroundTasks` processing
- **Processing** (background): read file bytes → chunk → embed each chunk via OpenAI → batch-insert into `chunks` table → update `ingestion_jobs` status to `complete` or `error`
- **Realtime**: Frontend subscribes to `ingestion_jobs` table changes via Supabase Realtime JS client. Backend doesn't need to push — Supabase Realtime picks up DB writes automatically.
- **Chunking**: Fixed-size by character count: `chunk_size=1000`, `overlap=200`. Simple and predictable.
- **Embedding model**: `text-embedding-3-small`, 1536 dimensions.

```sql
-- Enable pgvector
create extension if not exists vector;

-- Drop openai_thread_id column (no longer needed)
alter table public.threads drop column if exists openai_thread_id;

-- Documents table
create table public.documents (
  id           uuid primary key default gen_random_uuid(),
  user_id      uuid not null references auth.users(id) on delete cascade,
  name         text not null,
  size         bigint not null,
  mime_type    text not null,
  storage_path text not null,
  status       text not null default 'pending' check (status in ('pending','processing','complete','error')),
  created_at   timestamptz not null default now()
);
alter table public.documents enable row level security;
create policy "documents: users see own rows"
  on public.documents for all
  using (auth.uid() = user_id) with check (auth.uid() = user_id);

-- Chunks table (pgvector)
create table public.chunks (
  id           uuid primary key default gen_random_uuid(),
  document_id  uuid not null references public.documents(id) on delete cascade,
  user_id      uuid not null references auth.users(id) on delete cascade,
  content      text not null,
  chunk_index  int not null,
  embedding    vector(1536),
  created_at   timestamptz not null default now()
);
alter table public.chunks enable row level security;
create policy "chunks: users see own rows"
  on public.chunks for all
  using (auth.uid() = user_id) with check (auth.uid() = user_id);
create index on public.chunks using ivfflat (embedding vector_cosine_ops) with (lists = 100);

-- Ingestion jobs table (for Realtime status)
create table public.ingestion_jobs (
  id            uuid primary key default gen_random_uuid(),
  document_id   uuid not null references public.documents(id) on delete cascade,
  user_id       uuid not null references auth.users(id) on delete cascade,
  status        text not null default 'pending' check (status in ('pending','processing','complete','error')),
  error_message text,
  created_at    timestamptz not null default now(),
  updated_at    timestamptz not null default now()
);
alter table public.ingestion_jobs enable row level security;
create policy "ingestion_jobs: users see own rows"
  on public.ingestion_jobs for all
  using (auth.uid() = user_id) with check (auth.uid() = user_id);

create trigger ingestion_jobs_updated_at
  before update on public.ingestion_jobs
  for each row execute procedure public.set_updated_at();

-- pgvector similarity search function
create or replace function match_chunks(
  query_embedding vector(1536),
  match_user_id   uuid,
  match_count     int default 5,
  match_threshold float default 0.7
)
returns table (content text, document_name text, similarity float)
language plpgsql as $$
begin
  return query
  select
    c.content,
    d.name as document_name,
    1 - (c.embedding <=> query_embedding) as similarity
  from public.chunks c
  join public.documents d on d.id = c.document_id
  where c.user_id = match_user_id
    and 1 - (c.embedding <=> query_embedding) > match_threshold
  order by c.embedding <=> query_embedding
  limit match_count;
end;
$$;
```

**Task 2.3 — Create `services/llm_service.py`** ⚠️ Medium `[Wave 2]`

This is the core of the provider abstraction. It must:
1. Initialize the Chat Completions client from config
2. Define the `retrieve_chunks` tool schema
3. Implement `stream_chat_response()` that handles tool-calling interruption

```python
from openai import OpenAI
from config import settings
from langsmith import traceable
from typing import Iterator, Callable
import json

_client = OpenAI(
    base_url=settings.llm_base_url,
    api_key=settings.llm_api_key,
)

RETRIEVE_TOOL = {
    "type": "function",
    "function": {
        "name": "retrieve_chunks",
        "description": "Search the user's document knowledge base for relevant information. Call this when answering questions that may be answered by uploaded documents.",
        "parameters": {
            "type": "object",
            "properties": {
                "query": {
                    "type": "string",
                    "description": "The search query to find relevant document chunks",
                }
            },
            "required": ["query"],
        },
    },
}

@traceable(name="chat_completions_stream", run_type="llm")
def stream_chat_response(
    messages: list[dict],
    retrieval_fn: Callable[[str], str],
    user_id: str,
) -> Iterator[str]:
    """
    Stream a chat response using Chat Completions API.
    Handles one round of tool calling (retrieve_chunks) then streams final response.
    retrieval_fn: callable that takes query str and returns context str
    """
    # Pass 1: may trigger tool call
    stream = _client.chat.completions.create(
        model=settings.llm_model,
        messages=messages,
        tools=[RETRIEVE_TOOL],
        tool_choice="auto",
        stream=True,
    )

    tool_call_id = None
    tool_call_name = None
    tool_args_chunks = []

    for chunk in stream:
        delta = chunk.choices[0].delta if chunk.choices else None
        if delta is None:
            continue

        # Accumulate tool call
        if delta.tool_calls:
            tc = delta.tool_calls[0]
            if tc.id:
                tool_call_id = tc.id
            if tc.function.name:
                tool_call_name = tc.function.name
            if tc.function.arguments:
                tool_args_chunks.append(tc.function.arguments)
        elif delta.content:
            yield delta.content

    # If a tool was called, execute it and do Pass 2
    if tool_call_id and tool_call_name == "retrieve_chunks":
        args = json.loads("".join(tool_args_chunks))
        query = args.get("query", "")
        context = retrieval_fn(query)

        # Append assistant tool-call message + tool result to history
        messages = messages + [
            {
                "role": "assistant",
                "tool_calls": [{
                    "id": tool_call_id,
                    "type": "function",
                    "function": {"name": "retrieve_chunks", "arguments": "".join(tool_args_chunks)},
                }],
            },
            {
                "role": "tool",
                "tool_call_id": tool_call_id,
                "content": context,
            },
        ]

        # Pass 2: stream final answer (no tools this time)
        stream2 = _client.chat.completions.create(
            model=settings.llm_model,
            messages=messages,
            stream=True,
        )
        for chunk in stream2:
            delta = chunk.choices[0].delta if chunk.choices else None
            if delta and delta.content:
                yield delta.content
```

**Validation**: Integration test: call with a simple message list and verify text yields.

def _get_or_create_thread(user_id: str, thread_id: str | None) -> dict:
    if thread_id:
        result = supabase.table("threads").select("*").eq("id", thread_id).eq("user_id", user_id).single().execute()
        if not result.data:
            raise HTTPException(status_code=404, detail="Thread not found")

    return result.data[0]

New `_sse_generator()` structure:
```python
def _sse_generator(message, thread, user_id):
    _save_message(thread["id"], user_id, "user", message)
    
    # Load history including the message just saved
    history = _load_history(thread["id"])
    messages = [
        {"role": "system", "content": settings.llm_system_prompt},
        *history,
    ]
    
    retrieval_fn = lambda query: _retrieve(query, user_id)
    
    full_response = []
    try:
        for chunk in stream_chat_response(messages, retrieval_fn, user_id):
            full_response.append(chunk)
            yield f"data: {json.dumps({'delta': chunk, 'thread_id': thread['id']})}\n\n"
    except Exception as e:
        yield f"data: {json.dumps({'error': str(e)})}\n\n"
        return
    
    _save_message(thread["id"], user_id, "assistant", "".join(full_response))
    if thread.get("title") == "New Chat":
        supabase.table("threads").update({"title": message[:60]}).eq("id", thread["id"]).execute()
    yield f"data: {json.dumps({'done': True, 'thread_id': thread['id']})}\n\n"
```

**Note**: Save the user message first, then load history — this ensures the current user message is included in the history sent to the LLM.

```python
def chunk_text(text: str, chunk_size: int = 1000, overlap: int = 200) -> list[str]:
    chunks = []
    start = 0
    while start < len(text):
        end = start + chunk_size
        chunks.append(text[start:end])
        start += chunk_size - overlap
    return chunks
```

**Task 3.2 — Create `routers/ingest.py`** ⚠️ Medium `[Wave 3]`

Endpoints:
- `POST /ingest/upload` — multipart file upload
- `GET /ingest/documents` — list user's documents

Upload flow:
1. Read file bytes from `UploadFile`
2. Upload to Supabase Storage bucket `documents` at path `{user_id}/{document_id}/{filename}`
3. Insert `documents` row (status: `pending`)
4. Insert `ingestion_jobs` row (status: `pending`)
5. Add background task: `_process_document(document_id, file_bytes, user_id)`
6. Return `{"document_id": ..., "job_id": ...}`

Background processing function `_process_document()`:
1. Update job status → `processing`
2. Decode file bytes to text (UTF-8; plaintext and markdown only for Module 2)
3. Call `chunk_text(text)` → list of strings
4. For each chunk: call `embed_text(chunk)` → vector
5. Batch insert all chunks into `chunks` table
6. Update `documents.status` → `complete`; update job status → `complete` (or `error` on exception with `error_message`)
