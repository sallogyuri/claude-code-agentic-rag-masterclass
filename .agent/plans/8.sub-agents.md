# Module 8: Sub-Agents

🔴 **Complex** — spans 8 files, breaks `stream_chat_response` signature, cascades through all existing tests

## Context

The app currently has a single-tool two-pass architecture: the LLM either calls `retrieve_chunks` once or responds directly. Module 8 replaces this with a proper agentic loop, adds a `spawn_sub_agent` tool so the main agent can delegate full-document analysis to an isolated sub-agent with its own context, and surfaces all agent activity (tool calls, sub-agent work) in the chat UI.

**What the user learns:** Context management, agent delegation, hierarchical agent display, when to isolate.

---

## SSE Event Schema

All events: `data: <JSON>\n\n`. New typed format replaces implicit payload keys:

| type | key fields |
|------|-----------|
| `delta` | `delta`, `thread_id` |
| `tool_call_start` | `tool`, `args`, `thread_id` |
| `tool_call_end` | `tool`, `thread_id` |
| `sub_agent_start` | `task`, `document`, `thread_id` |
| `sub_agent_tool_call` | `tool`, `query`, `thread_id` |
| `sub_agent_delta` | `delta`, `thread_id` |
| `sub_agent_end` | `thread_id` |
| `done` | `thread_id` |
| `error` | `error`, `thread_id` |

### Task 1 — `backend/services/sub_agent_service.py` (NEW)

```python
@traceable(name="sub_agent_stream", run_type="llm")
def run_sub_agent_stream(
    task: str,
    document_name: str,
    user_id: str,
    retrieval_fn: Callable[[str, dict | None], str],
) -> Iterator[dict]:
```

- System prompt: `f"You are a document analyst for '{document_name}'. Task: {task}. Use retrieve_chunks multiple times if needed."`
- Tools: **only** `RETRIEVE_TOOL` imported from `llm_service` — no `spawn_sub_agent` (prevents recursion)
- Agentic loop: same multi-tool accumulation pattern as Task 2
- Yields: `{"type": "sub_agent_delta", "delta": str}` and `{"type": "sub_agent_tool_call", "tool": "retrieve_chunks", "query": str}`
- `MAX_SUB_AGENT_ITERATIONS = 5` guard — break loop if exceeded
- On any exception: yield `{"type": "sub_agent_delta", "delta": f"\n[Sub-agent error: {str(e)}]"}` then return

### Task 2 — `backend/services/llm_service.py` (MODIFY)

**Add** `SPAWN_SUB_AGENT_TOOL` constant after `RETRIEVE_TOOL`.

**Replace two-pass with agentic loop.** New signature:
```python
def stream_chat_response(
    messages: list[dict],
    retrieval_fn: Callable[[str, dict | None], str],
    sub_agent_fn: Callable[[str, str], Iterator[dict]],
    user_id: str,
) -> Iterator[dict]:
```

**Multi-tool accumulation** (replaces single scalar approach):
```python
tool_calls_by_index: dict[int, dict] = {}
# {"id": str, "name": str, "args_chunks": list[str]}
# key = tc.index (use getattr(tc, 'index', 0) or 0 as fallback)
```

**Loop structure:**
```
while iteration < MAX_ITERATIONS (10):
    stream → accumulate tool calls OR yield {"type": "delta", "delta": text}
    if finish_reason == "stop" or no tool calls: break
    append assistant message with tool_calls array
    for each tool call in sorted(tool_calls_by_index):
        if retrieve_chunks:
            yield tool_call_start → call retrieval_fn → yield tool_call_end
        if spawn_sub_agent:
            yield sub_agent_start → yield from sub_agent_fn(task, doc) → yield sub_agent_end
        append tool result message
    continue loop
```

`finish_reason` is read from the **last** chunk's `choice.finish_reason`, not per-chunk.

### Task 4 — `frontend/src/hooks/useChat.ts` (MODIFY)

**New types** (export both):
```typescript
export interface AgentEvent {
  type: 'tool_call_start' | 'tool_call_end' | 'sub_agent_start'
       | 'sub_agent_tool_call' | 'sub_agent_delta' | 'sub_agent_end'
  tool?: string
  args?: { query?: string; metadata_filter?: Record<string, unknown> | null }
  task?: string
  document?: string
  query?: string
  delta?: string
}

export interface Message {
  id: string
  role: 'user' | 'assistant'
  content: string
  created_at: string
  events?: AgentEvent[]       // ordered agent events
  subAgentContent?: string    // accumulated sub-agent text buffer
}
```

**Update SSE parser** — handle both old-style (`payload.delta` without type) and new typed events:
- `payload.type === 'delta'` or `!payload.type && payload.delta` → append to `message.content`
- `payload.type === 'sub_agent_delta'` → append to `message.subAgentContent`
- structured event types → push to `message.events` array
- `payload.type === 'done'` or `payload.done` → handle thread reload (support both formats)

## Pitfalls

1. **`tc.index` may be None** — guard: `idx = getattr(tc, 'index', 0) or 0`
2. **`finish_reason` timing** — read from last chunk only, not per-chunk (can be None mid-stream)
3. **Sub-agent output in saved message** — `_sse_generator` must append `sub_agent_delta` text to `full_response_parts` so the DB message isn't empty when only sub-agent ran
4. **Test signature breakage** — update existing `test_llm_service.py` calls before running suite
5. **SSE done format** — frontend must handle both `{"done": true}` (old) and `{"type": "done"}` (new)
