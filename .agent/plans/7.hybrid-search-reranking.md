# Plan: Module 6 — Hybrid Search & Reranking

⚠️ **Medium** — Two new service files, one DB migration, one function update. No interface changes.

## Context

Pure vector search has a known failure mode: exact keyword matches on rare terms (product names, codes, proper nouns) score poorly because the embedding model smooths over them semantically. Full-text keyword search (FTS) fills this gap but lacks semantic understanding. Module 6 combines both via Reciprocal Rank Fusion (RRF) for candidate retrieval, then adds an LLM reranking pass to select the final top-K results returned to the chat agent.

The only external-facing change is to `_retrieve()` in `chat.py` — the retrieval tool's interface stays identical; only its internals change.

### Task 2: Hybrid Search Service

**File:** `backend/services/hybrid_search_service.py`

Functions:

**`_vector_search(query, user_id, supabase_client, count, threshold, metadata_filter)`**
- Calls existing `match_chunks` RPC (same as current `_retrieve()`)
- Returns list of dicts: `{chunk_id, content, document_name, score}`
- Use `match_count=10`, `match_threshold=0.1` (low threshold — we want candidates, not final results)

**`_keyword_search(query, user_id, supabase_client, count, metadata_filter)`**
- Calls new `keyword_search_chunks` RPC
- Returns list of dicts: `{chunk_id, content, document_name, score}`

**`_reciprocal_rank_fusion(vector_results, keyword_results, k=60)`**
- RRF formula: `score += 1 / (k + position)` for each list a chunk appears in (1-indexed position)
- Deduplicates by `chunk_id`
- Returns all chunks sorted by RRF score descending

**`hybrid_search(query, user_id, supabase_client, candidate_count=10, metadata_filter=None)`**
- Calls `_vector_search` and `_keyword_search` in sequence
- Calls `_reciprocal_rank_fusion` to merge results
- Returns top `candidate_count` chunks as list of dicts: `{content, document_name, rrf_score}`

**Validation:** Unit tests (see Task 5).

### Task 3: Reranking Service

**File:** `backend/services/reranking_service.py`

Uses the existing `_client` from `llm_service.py` and `settings.llm_model` — no new dependencies.

**Pydantic models (consistent with `metadata_service.py` pattern):**
```python
class ChunkScore(BaseModel):
    index: int      # 0-based index in the input list
    score: float    # 0.0–1.0 relevance to query

class RerankResponse(BaseModel):
    scores: list[ChunkScore]
```

**`rerank_chunks(query, chunks, top_k=5)`**
- If `len(chunks) <= top_k`, return as-is (no LLM call needed)
- Build a prompt listing each chunk with its index: `[0] <content>`, `[1] <content>`, …
- System prompt instructs: return JSON `{scores: [{index: N, score: F}, ...]}` where score is 0.0–1.0 relevance
- Calls `_client.chat.completions.create()` with `response_format={"type": "json_object"}`, `stream=False`
- Parses with `RerankResponse.model_validate_json()`
- Sorts original chunks by returned scores descending, returns top `top_k`
- On any exception: fall back to returning `chunks[:top_k]` unmodified (reranking is non-critical)
- Truncate each chunk content to 500 chars before sending to reranker (avoid huge prompts)

### Task 4: Update `_retrieve()` in Chat Router

**File:** `backend/routers/chat.py`

Add imports:
```python
from services.hybrid_search_service import hybrid_search
from services.reranking_service import rerank_chunks
```

Replace the body of `_retrieve()` (lines 66–86) with:
```python
def _retrieve(query: str, user_id: str, metadata_filter: dict | None = None) -> str:
    candidates = hybrid_search(query, user_id, supabase, candidate_count=10, metadata_filter=metadata_filter)
    top_chunks = rerank_chunks(query, candidates, top_k=5)

    if not top_chunks:
        return "No relevant documents found."

    parts = []
    for chunk in top_chunks:
        parts.append(f"[From: {chunk['document_name']}]\n{chunk['content']}")
    return "\n\n---\n\n".join(parts)
```

Remove the now-unused `embed_text` import from `chat.py` (it moves inside `hybrid_search_service.py`).
