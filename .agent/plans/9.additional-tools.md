# Module 7: Additional Tools — Text-to-SQL + Web Search

⚠️ **Medium** — Two new services, new tool definitions, agentic loop extension, new env vars, ~20 new tests

## Context

The app currently answers questions using three tools: `retrieve_chunks` (vector/keyword search), `spawn_sub_agent` (full-document analysis), and has no way to answer questions that require either structured data queries (e.g. "how many documents have I uploaded?", "which files failed to process?") or information not in the uploaded documents (e.g. current events, general knowledge).

Module 7 adds two new tools:
1. **`text_to_sql`** — LLM generates SQL to query the user's Supabase tables; answers questions about structured data (document stats, thread history, ingestion status)
2. **`web_search`** — Tavily-powered fallback for when the knowledge base has no relevant results; returns results with source URLs so the LLM can cite them

**What the user learns:** Multi-tool agents, routing between structured/unstructured data, graceful fallbacks, attribution for trust.

### Task 2 — `backend/services/text_to_sql_service.py` (NEW)

```python
import psycopg2
import psycopg2.extras
import re
from openai import OpenAI
from config import settings
from langsmith import traceable

# Tables exposed to the LLM — user-scoped only, no internal/system tables
SCHEMA_DESCRIPTION = """
Available tables (all rows are scoped to the authenticated user via user_id):

documents(id UUID, name TEXT, size INTEGER, mime_type TEXT, status TEXT, created_at TIMESTAMPTZ, metadata JSONB)
  - status values: 'pending' | 'processing' | 'complete' | 'error'
  - metadata keys (if present): document_type, language, author, title, summary

chunks(id UUID, document_id UUID, content TEXT, chunk_index INTEGER, created_at TIMESTAMPTZ)
  - each document is split into multiple chunks

threads(id UUID, title TEXT, created_at TIMESTAMPTZ, updated_at TIMESTAMPTZ)

messages(id UUID, thread_id UUID, role TEXT, created_at TIMESTAMPTZ)
  - role values: 'user' | 'assistant'
"""

_llm = OpenAI(base_url=settings.llm_base_url, api_key=settings.llm_api_key)

SQL_GEN_PROMPT = (
    "You are a SQL expert. Generate a single valid PostgreSQL SELECT query to answer "
    "the user's question using the schema below. Rules:\n"
    "1. Only SELECT statements — no INSERT, UPDATE, DELETE, DROP, etc.\n"
    "2. Always include WHERE user_id = '{user_id}' (or user_id filter via JOIN) "
    "to scope results to the authenticated user.\n"
    "3. Return only the SQL — no explanation, no markdown fences.\n\n"
    "Schema:\n{schema}"
)


def _generate_sql(query: str, user_id: str) -> str:
    prompt = SQL_GEN_PROMPT.format(user_id=user_id, schema=SCHEMA_DESCRIPTION)
    response = _llm.chat.completions.create(
        model=settings.llm_model,
        messages=[
            {"role": "system", "content": prompt},
            {"role": "user", "content": query},
        ],
    )
    return response.choices[0].message.content.strip()


def _validate_sql(sql: str, user_id: str) -> None:
    """Raises ValueError if SQL is not a safe SELECT scoped to user_id."""
    sql_lower = sql.strip().lower()
    if not sql_lower.startswith("select"):
        raise ValueError("Only SELECT queries are permitted")
    forbidden = r"\b(insert|update|delete|drop|create|alter|truncate|grant|revoke|execute|copy)\b"
    if re.search(forbidden, sql_lower):
        raise ValueError("Query contains a forbidden keyword")
    if user_id.lower() not in sql_lower:
        raise ValueError("Query must include user_id filter for data isolation")


def _execute_sql(sql: str) -> list[dict]:
    """Execute query in a read-only transaction, return rows as list of dicts."""
    with psycopg2.connect(settings.database_url) as conn:
        conn.set_session(readonly=True, autocommit=False)
        with conn.cursor(cursor_factory=psycopg2.extras.RealDictCursor) as cur:
            cur.execute(sql)
            rows = cur.fetchmany(100)  # cap at 100 rows
            return [dict(row) for row in rows]


@traceable(name="text_to_sql", run_type="tool")
def text_to_sql(query: str, user_id: str) -> str:
    """
    Translate a natural-language query into SQL, execute it, and return formatted results.
    Returns an error string (not raised) if generation or execution fails.
    """
    try:
        sql = _generate_sql(query, user_id)
        _validate_sql(sql, user_id)
        rows = _execute_sql(sql)
    except Exception as e:
        return f"[text_to_sql error: {e}]"

    if not rows:
        return "Query returned no results."

    # Format as a readable table-like string
    headers = list(rows[0].keys())
    lines = [" | ".join(headers)]
    lines.append("-" * len(lines[0]))
    for row in rows:
        lines.append(" | ".join(str(row[h]) for h in headers))
    return "\n".join(lines)
```

### Task 3 — `backend/services/web_search_service.py` (NEW)

```python
from tavily import TavilyClient
from config import settings
from langsmith import traceable


@traceable(name="web_search", run_type="tool")
def web_search(query: str) -> str:
    """
    Search the web using Tavily and return formatted results with source attribution.
    Returns an error string (not raised) if the search fails.
    """
    try:
        client = TavilyClient(api_key=settings.tavily_api_key)
        response = client.search(query, max_results=5, include_answer=True)
    except Exception as e:
        return f"[web_search error: {e}]"

    parts = []

    # Include Tavily's synthesized answer if present
    if response.get("answer"):
        parts.append(f"Summary: {response['answer']}\n")

    for result in response.get("results", []):
        title = result.get("title", "No title")
        url = result.get("url", "")
        content = result.get("content", "")[:400]  # trim long snippets
        parts.append(f"**{title}**\nURL: {url}\n{content}")

    return "\n\n---\n\n".join(parts) if parts else "No results found."
```

## Pitfalls

1. **psycopg2 read-only transaction** — use `conn.set_session(readonly=True)` before executing; this prevents any accidental writes even if LLM generates DML
2. **user_id check is string-based** — the validation checks `user_id.lower() in sql_lower`; LLM must include the literal UUID, not a placeholder. The `_generate_sql` prompt interpolates it directly.
3. **Tavily `include_answer`** — set to `True` to get the synthesized answer; not all queries return one so guard with `.get("answer")`
4. **conftest mock order** — psycopg2 and Tavily patches must be applied BEFORE `from main import app` to prevent import-time connection attempts
5. **llm_service signature change breaks existing tests** — update all callers in `test_llm_service.py` and `test_chat_routes.py` before running the suite
6. **`test_chat_routes.py`** — the `stream_chat_response` mock there patches at `routers.chat.stream_chat_response`, not the service directly; the signature change doesn't affect it (mock returns directly), but verify it still passes
