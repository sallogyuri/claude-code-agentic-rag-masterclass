# Module 3: Record Manager

⚠️ **Medium** — Two backend layers (DB migration + new service), small ingest router changes, minor frontend feedback updates. Straightforward but touches several files.

## Context

Module 2 ingests naively: uploading the same file twice creates duplicate chunks, degrading retrieval quality. There is no content hashing, no duplicate detection, and no change tracking. Module 3 introduces a **Record Manager** that hashes file content on upload, detects exact duplicates (skip re-ingestion), and handles updates (same filename, new content → replace old document and re-process).

**Goal:** Users can freely re-upload files. Unchanged files are skipped. Modified files replace the old version. Retrieval quality stays clean.

---

## Plan

### 1. DB Migration — `supabase/migrations/003_module3_schema.sql`

Add `content_hash` column to `documents` and an index for fast lookup:

```sql
ALTER TABLE documents ADD COLUMN content_hash text;
CREATE INDEX idx_documents_user_hash ON documents(user_id, content_hash);
```

No new tables needed. The index enables O(log n) duplicate lookups by user.

---

### 2. New Service — `backend/services/record_manager.py`

Three functions:

```python
def compute_file_hash(file_bytes: bytes) -> str:
    """SHA-256 hex digest of raw file bytes."""
    return hashlib.sha256(file_bytes).hexdigest()

async def find_duplicate_by_hash(supabase, user_id: str, content_hash: str) -> dict | None:
    """Return existing document row if user already has a doc with this hash."""

async def find_document_by_name(supabase, user_id: str, name: str) -> dict | None:
    """Return existing document row if user has a doc with this filename."""
```

No side effects — pure lookups. The router decides what to do with the results.

---

### 3. Modify Upload Handler — `backend/routers/ingest.py`

Insert record-manager logic at the top of `POST /ingest/upload`, **before** any storage write:

```
file_bytes = await file.read()
content_hash = compute_file_hash(file_bytes)

# Case 1: Exact duplicate (same hash) → return existing document, no re-processing
existing = await find_duplicate_by_hash(supabase, user_id, content_hash)
if existing:
    return {"document_id": existing["id"], "job_id": None, "duplicate": True}

# Case 2: Same filename, different hash → it's an update, delete old doc first
old = await find_document_by_name(supabase, user_id, file.filename)
if old:
    # Delete old storage file + DB record (chunks cascade-delete via FK)
    supabase.storage.from_("documents").remove([old["storage_path"]])
    supabase.table("documents").delete().eq("id", old["id"]).execute()

# Case 3: New file → proceed as normal, store content_hash on insert
```

Also update the `documents` insert to include `content_hash`.

**Response shape change:**
```python
# Before
{"document_id": str, "job_id": str}

# After
{"document_id": str, "job_id": str | None, "duplicate": bool}
```
